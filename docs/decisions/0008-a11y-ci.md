# Accessibility check in CI: axe-core + Playwright (2026-11-02, Dev bot)
## Context
Issue #61. CI should fail on new WCAG 2.0/2.1 A/AA violations in the core learner flow: login, placement, path head (map view and engagement session card), step player (hint open, wrong choice feedback, step done). Each at 375 and 1280 px, light and dark. Under 3 minutes, Chromium only, pinned versions, not a required check at first.
## Options considered
| Option | Pros | Cons |
|---|---|---|
| A (chosen) Python: `playwright` 1.64.1 + `axe-playwright-python` 0.1.8 (axe-core 4.12.1 bundled), plain pytest | same language and pytest as core-tests; reuses the CI content vendoring, the dev mail console sign in and the hint/feedback test path; no Node toolchain or lockfile; one session scoped browser context is simple to write | axe-core version moves only with the wrapper release; smaller community than the Node package |
| B Node: `@playwright/test` + `@axe-core/playwright` | official Deque package, axe-core pinned directly, HTML reporter, traces | adds package.json/lockfile and Node setup to a Python repo; server start and seeding written twice; per test contexts by default |
| C pa11y / lighthouse-ci against URLs | no test code | cannot drive sign in, htmx answers or the hint; slower; weaker per state control |
## Decision
A. Lowest new surface for a Python repo, and the flow needs real interactions (sign in, start, click choices) that a URL scanner cannot do.
- `packages/core/tests_a11y/`: outside `testpaths`, so `pytest` in core-tests never collects it.
- `conftest.py` starts uvicorn (`myroad_core.ui.app:app`) on a temp SQLite DB and a temp CONTENT_DIR (vendored content plus `path_a11y_step_player.json`, the path from `tests/test_step_hint_feedback_ui.py` with hint and per choice feedback). Sign in goes through the real form; the code is read from the dev mail console (`MYROAD_DEV_MAIL_CONSOLE=1`).
- Theme: the app follows `prefers-color-scheme` unless the learner set one, so the test emulates the color scheme (and reduced motion, to scan settled colors).
- One Chromium, one context, one page; each state is scanned in 4 combos. A JSON report of every violation is uploaded as an artifact.
- `allowlist.json`: known violations (rule + selector + state + reason + issue link) do not fail; anything new does. Empty today: the first run found 0 violations.
- Workflow `.github/workflows/a11y.yml`, job `a11y`; Chromium cached by the requirements hash.
## How to switch
To B: add `e2e/a11y/package.json` pinning `@playwright/test` and `@axe-core/playwright`, port `test_axe_learner_flow.py` (states, `withTags([...])`, allowlist filter) and start the server with Playwright `webServer` using the same env as `conftest.py`; swap the Python steps in `a11y.yml` for `actions/setup-node` + `npx playwright install chromium`.
To make it blocking: add `a11y` to the required checks after about 5 green runs on main.
